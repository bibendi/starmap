# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `McpController` регистрирует только `TeamMetricsTool`; `period_id` выбирается через `AssessmentPeriod.find_by`, а пропущенный ID — через `AssessmentPeriod.current`. Модель уже предоставляет `ordered`, `full_name` и все необходимые поля.

`McpBaseTool` маршрутизирует Pundit policy по типу identity. Существующая `Admin::AssessmentPeriodPolicy` управляет административным доступом и не подходит для engineer или team_lead. В `ApiClient::AVAILABLE_PERMISSIONS` есть только `teams:read` и `units:read`. Список периодов общий и не содержит командных данных.

Design необходим из-за нового read-only authorization boundary и небольшого изменения общего MCP helper. Конфликта с основной спецификацией нет: добавляется discovery, существующий селектор периода сохраняется.

## Goals / Non-Goals

**Goals:**
- Замкнуть сценарий discovery → выбор исторического ID → метрики, в том числе без текущего периода.
- Отделить глобальные метаданные периодов от администрирования и командных метрик.
- Использовать существующие MCP helpers и модель без нового слоя абстракций.

**Non-Goals:**
- Не расширять административную policy и не обходить командную policy метрик.
- Не вычислять «прошлый квартал» на сервере: агент сопоставляет запрос с явными датами.
- Не добавлять query object для одного упорядоченного чтения без JOIN или агрегаций.

## Decisions

### 1. Инструмент без параметров с явным whitelist ответа

Добавить `AssessmentPeriodsTool < McpBaseTool`, `tool_name "assessment_periods"`, пустую объектную input schema и `execute(server_context:)`. Использовать те же annotations и `text_response`, что у инструмента метрик. Сериализовать `{"periods": [...]}`; `name` брать из `full_name`, даты — явно в ISO 8601, поля — только из контракта delta spec.

Альтернатива: возвращать ActiveRecord `as_json` без whitelist. Отклонена из-за служебных полей и риска случайного расширения API при изменении модели. Обёртка `periods` яснее голого массива и допускает совместимое добавление метаданных в будущем.

### 2. Общий полный каталог в существующем порядке

Читать `AssessmentPeriod.ordered`, без фильтра по статусу, команде, наличию оценок или текущему периоду. Это совпадает с timeline модели и возможностью `team_metrics` выбрать любой существующий период. Не исключать draft: текущая модель даже может пометить первый draft как текущий.

Альтернативы: только закрытые периоды; обязательное имя команды; фильтры и пагинация. Первое скрывает допустимые ID, второе связывает общий справочник с командой, остальные усложняют небольшой каталог без текущей необходимости. Не вводить скрытый лимит, который делает старые ID недоступными.

### 3. Отдельные policies чтения метаданных

Добавить обычную `AssessmentPeriodPolicy#index?` для аутентифицированного User и `ApiClient::AssessmentPeriodPolicy#index?` для включённого ApiClient с `teams:read`. Использовать существующий `authorize(identity, AssessmentPeriod, :index)` до чтения каталога. Не добавлять permissions и не менять `Admin::AssessmentPeriodPolicy`.

Зафиксированное допущение: метаданные всех статусов, включая draft, доступны всем ролям; это не доступ к оценкам и не право управления периодами. `units:read` отдельно недостаточно, поскольку текущий downstream MCP tool требует `teams:read`.

Альтернативы: административная policy исключит основных потребителей MCP; только проверка аутентификации игнорирует ограничения ApiClient; новое `assessment_periods:read` требует перенастройки клиентов без необходимости.

### 4. Class-level отказ должен оставаться штатной MCP ошибкой

Сейчас `McpBaseTool#authorize` при отказе строит подпись через `record.name` или `record.id`; для model class `name` есть, но дальнейшее `record.class.name` даёт `Class`, а не доменную сущность. При добавлении class-level авторизации нормализовать название ресурса для class и instance, сохранив текущий формат отказа для экземпляра Team. Policy resolution остаётся прежним; обработчик отказа не должен вызывать отсутствующие методы.

Проверять class-level denied и instance-level denied через реальные HTTP-вызовы инструментов в отдельных request specs; матрицу прав проверять в policy specs. Отдельные unit specs инструментов и базового класса не нужны. Не вводить отдельную инфраструктуру авторизации для одного инструмента.

### 5. Discovery через существующий endpoint и подсказки

Добавить инструмент в `tools:` сервера рядом с `TeamMetricsTool`. В описании `period_id` и ошибке `No current assessment period` указать `assessment_periods`. Сохранить существующие узнаваемые части сообщения и успешный payload метрик. В `docs/mcp.md` описать инструменты, параметры, ответы и два JSON-RPC вызова: каталог → метрики с выбранным ID; добавить ссылку на `docs/auth.md` для настройки доступа. В `docs/auth.md` оставить общие правила аутентификации и маршрутизации policies; права конкретных инструментов описать в `docs/mcp.md`.

## Risks / Trade-offs

- [Раскрытие названий draft всем потребителям метрик] → Явно ограничить payload метаданными; не менять доступ к оценкам и админке; покрыть policies тестами.
- [Рост полного каталога] → Сейчас количество периодов ограничено бизнес-частотой их создания; фильтры и пагинацию добавлять отдельным изменением при подтверждённой необходимости, не обрезать результат молча.
- [Регрессия общего MCP helper] → Минимальная правка подписи отказа и тесты обоих видов record; сохранить `TeamMetricsTool` regression suite.
- [Неверные ожидания вокруг current] → Передавать сохранённый `is_current`, не подменять его проверкой active или дат; тестировать closed/current и отсутствие current.
- [Тестовые периоды пересекаются] → Подбирать разнесённые интервалы с учётом существующей валидации; все общие persisted fixtures объявлять через top-level `let_it_be`.

## Migration Plan

Миграции БД и обновление разрешений существующих клиентов не нужны. Развернуть добавление инструмента, policies и подсказок вместе; клиенты обнаружат новый tool через `tools/list` (при необходимости обновив закэшированный список). Откат — возврат приложения на предыдущую версию; данные не меняются, существующий `team_metrics` остаётся совместимым.
